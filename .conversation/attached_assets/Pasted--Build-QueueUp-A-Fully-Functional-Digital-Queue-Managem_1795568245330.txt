# Build QueueUp – A Fully Functional Digital Queue Management SaaS MVP

Act as a senior full-stack software engineer, SaaS product architect, and UI/UX designer.

I want you to build a fully functional, responsive web application called **QueueUp**.

QueueUp is a digital queue management and online ticketing platform designed for businesses such as barbershops, medical clinics, beauty salons, car washes, restaurants, repair shops, and other service-based businesses.

The primary goal is to eliminate physical waiting lines and allow customers to join queues remotely using a simple public link, without installing an application or creating an account.

This must be a real working MVP, not just a visual prototype.

**IMPORTANT: Build this application specifically for the Replit Starter (Free) plan. Avoid paid services, unnecessary infrastructure, external APIs, and features that require a paid subscription. Use Replit's built-in database and the simplest reliable architecture.**

4. Average Waiting Time.

Display a live queue management table.

Suggested columns:

- Ticket Number.
- Customer Name.
- Joined At.
- Status.
- Actions.

### Queue Management Actions

All of the following actions must work and update the database:

**1. Call Next Customer**

- Find the oldest ticket with Waiting status.
- Change its status to Called.
- Update the current ticket information.
- Notify the customer through the live queue interface.

**2. Start Service**

- Change the Called ticket status to Serving.
- Record the service start timestamp.
- Update queue information.

**3. Complete Service**

- Change the Serving ticket status to Completed.
- Record completion timestamp.
- Update dashboard statistics.
- Recalculate waiting positions and estimated times.

**4. Skip Customer**

- Change the selected active ticket status to Skipped.
- Remove it from the active queue.
- Recalculate queue positions and estimated waiting times.

**5. Recall Current Customer**

- Re-display or re-announce the current Called or Serving ticket.
- Increment a recall counter or update the last-called timestamp.

**6. Pause Queue**

- Temporarily prevent new customer bookings.
- Display a clear paused status on the public booking page.
- Allow the business owner to continue serving existing customers.

**7. Resume Queue**

- Allow new customers to join again.
- Restore the normal queue booking functionality.

### Queue Rules

For the initial MVP, use one active service position per business.

There must never be more than one active ticket in Called or Serving status at the same time.

The Call Next button must be disabled when another ticket is already Called or Serving.

The owner must first start and complete the current service, or skip the current ticket, before calling the next customer.

Use FIFO (First In, First Out) ordering.

Display appropriate loading states, confirmation dialogs, and success/error messages for management operations.

### Business Settings

Allow the business owner to edit:

- Business Name.
- Business Category.
- Average Service Duration.
- Maximum Queue Capacity.

Keep these changes persistent in the database.

# 5. Queue Calculation Logic

Implement queue calculations on the backend.

Do not rely on frontend-only calculations.

### Sequential Ticket Generation

Each business has its own independent ticket counter.

Every new ticket receives the next number in sequence.

Example:

A-001
A-002
A-003
A-004

Use database transactions to prevent duplicate ticket numbers when multiple customers join simultaneously.

### Queue Position

Calculate a customer's position using the active ticket sequence.

Only tickets with Waiting, Called, or Serving status should contribute to active queue calculations.

### Estimated Waiting Time

Use the configured average service duration.

For customers waiting in line:

Estimated Wait =
Remaining Current Service Time + (Number of Waiting Customers Ahead × Average Service Duration)

If there is a Called ticket but service has not started, use one average service duration as its estimated service time.

If there is a Serving ticket, calculate the remaining estimated duration from its start timestamp.

Return the calculated position, people ahead, active queue size, and estimated waiting time from the backend.

Clearly indicate that waiting times are estimates.

Recalculate these values whenever a ticket changes status.
